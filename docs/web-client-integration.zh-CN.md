# 网页远控的角色授权与审计

网页远控由 Console 发放短期授权，再通过 Console 的透明 WebSocket 网关连接既有 hbbs/hbbr。网关不解密远端密码、画面、聊天或文件内容，也不要求维护新的 RustDesk 服务端分支。

## 配置

功能默认关闭。配置存储在 Console 数据库中，由超级管理员登录后在 **设置 -> Web 客户端** 页面管理；保存后立即生效，无需重启。需要填写的字段：

| 设置字段 | 说明 |
| --- | --- |
| 启用开关 | 开启后其余字段必须完整且有效 |
| 允许的来源 | 浏览器实际使用的完整 HTTPS origin |
| 公开 ID 服务器地址 | 对外发布的 `wss://` WebSocket 地址 |
| 公开中继服务器地址 | 对外发布的 `wss://` WebSocket 地址 |
| 服务器公钥 | hbbs/hbbr 生成的 base64 公钥（`id_ed25519.pub`） |
| 内部 ID 上游（可选） | 网关代理的容器网络上游，留空使用公开地址 |
| 内部中继上游（可选） | 网关代理的容器网络上游，留空使用公开地址 |

允许的来源必须是浏览器实际使用的完整 HTTPS origin，包含非默认端口，不带末尾斜杠或路径。例如 IP 部署可填写 `https://203.0.113.10:22443`（示例地址，部署时替换）。不能从请求的 Host 或代理头自动推断该值。

两个内部上游字段仅由后端使用，用来指定容器网络中的固定上游；留空时使用对应的公开 WSS 地址。公开地址仍用于原有客户端配置、公钥和记住密码的服务器身份绑定。请求体、浏览器收到的服务器广告均不能指定网关上游。

反向代理须将 `/api/web-client/socket` 的 WebSocket Upgrade 转发到 Console，并允许长连接。原生 TCP/UDP 端口和服务器密钥继续保留，但不能继续允许普通浏览器通过原有公开 `/ws/id`、`/ws/relay` 直通服务器，绕过 Console 授权。部署时须处理这些路径和裸 WS 端口的浏览器旁路，具体示例与兼容边界见 [网关部署说明](../deploy/web-client-gateway/README.zh-CN.md)。仅完成设置表单并不能替代反向代理配置。

配套前端的 Docker Nginx 已包含受控网关的精确路由。官方原生前端二进制当前只代理普通 HTTP，没有实现 WebSocket Upgrade；使用该二进制时，前置 HTTPS 反向代理必须将 `/api/web-client/socket` 直接转到 Console 后端，保留原始 `Origin`。不能先交给原生前端的 `/api/` 通用代理，也不能改为直通 hbbs/hbbr。此要求仅涉及部署入口，不需要改动原生 RustDesk 客户端或服务端。

授权和单次票据保存在当前 Console 进程内。当前实现适用于单 Console 实例；重启会关闭现有网页会话。多实例部署须让授权 HTTP 请求和对应 WebSocket 到达同一实例，不能在没有会话亲和性的情况下随机分发。

## 角色和设备范围

除系统所有者外，任何用户都须取得 `web_client.connect` 权限，自己的设备也不例外。`devices.view`、个人地址簿和原有设备 ACL 均不会隐式授予网页远控权限。

文件传输另需 `web_client.file_transfer`。角色必须在同一角色内同时包含 `web_client.connect`；服务端分别检查这两项权限的当前设备组范围。不会因为用户在另一个角色拥有连接权限，就接受一个缺少依赖的文件传输角色。

文件权限控制 Console 签发的独立文件通道和界面入口，不是内容级文件隔离。原生客户端的加密登录请求也包含用途，桌面通道中的加密内容无法由透明网关检查；明文信令用途并不等同于对该内容的原生绑定。需要严格禁用文件传输时，仍须在被控端关闭对应的原生权限，不能只撤掉 Console 的文件角色权限。

两项权限均支持全局或设备组范围。设备列表和手动输入 ID 的连接申请使用相同范围，只接受 Console 中 ACTIVE、ID 唯一的登记设备。未知、禁用、范围外、重复登记均拒绝连接；另一条重复登记即使禁用或在角色范围外，也不会被忽略。

原有 RustDesk 客户端 `/api/peers` ACL 行为保持不变。这里的角色规则约束 Console 网页通道；公开原生 TCP/WS 连接仍依赖 RustDesk 的密码、远端批准和原生功能权限，不能把它解释为对所有原生客户端的统一控制。

网页角色也不会绕过远端密码或批准。服务端只能强制桌面连接、文件连接及目标范围；加密数据中的剪贴板、只读、聊天等内容无法由透明网关逐项检查，因此没有增加只靠前端按钮实现的细粒度角色权限。

## 会话生命周期

每次申请绑定操作者 GUID、登录 JTI、登记设备 UUID、精确设备 ID、服务器配置及桌面/文件用途。两张票据各只能用一次，60 秒后失效；120 秒内未打开中继的授权被回收。每个账号最多 8 个授权，当前进程最多 256 个；活跃授权最多 8 小时，并受登录 token 和父桌面授权的期限进一步限制。

服务端按 15 秒周期串行复验当前登录 token、账号状态、角色范围、设备状态及 UUID/ID 绑定。每条验证以及整轮复验均有 5 秒上限。正常事件循环下，撤权检测窗口为轮询周期加整轮上限；进程暂停或事件循环停止时无法保证墙钟时间。

数据库或审计无响应达到上限时，会同步使全部授权失效并关闭相关通道。底层 TypeORM 查询不能强制取消，旧 I/O 返回前暂停新的授权；旧结果只解除健康门禁，不恢复已经关闭的连接。关闭多个文件子通道时，会先关闭全部 socket，再尽力写入结束审计，避免慢日志阻塞其它通道。

用户可以取消自己的会话。关闭他人的会话必须持有当前目标范围内的 `devices.disconnect`；只有 `audit.view` 无权断开。桌面父会话关闭时，同时结束其所有文件子会话。已经结束的会话重复取消返回已结束，不产生虚假的再次执行日志。

文件授权的父会话“活跃”表示服务端中继通道已打开，不等同于服务器独立验证远端密码成功。文件连接仍执行原生认证，浏览器可以复用此前认证材料，但不能以浏览器成功报告升级服务端信任。

## 审计字段和证据边界

沿用 `console_audits`，不新增数据库表。网页记录的 `target_type` 为 `web_client_session`，`target_guid` 和 `request_id` 为授权会话 GUID；操作者 GUID 始终由服务端上下文确定。

| 来源      | 事件                                                                  |
| --------- | --------------------------------------------------------------------- |
| `server`  | 申请准许/拒绝、中继通道开启、取消、管理员断开、撤权、过期、错误及结束 |
| `browser` | 浏览器报告的远端认证成功/失败，文件上传/下载开始、完成、失败          |

`after_state` 只保存目标 ID、登记 UUID、用途、父会话、事件、来源、服务端事件时间以及有限的文件名/大小/方向。管理员结束记录的操作者为执行管理员，`closedBy` 也指向该管理员。合法且通过格式校验的拒绝申请会记录其请求 ID；无效原始输入和他人会话内部信息不会写入拒绝元数据。

浏览器认证失败、文件失败的 `result` 为 `denied`，表示该报告的失败结果，不能将其解释为服务端独立确认的授权拒绝。

不会保存密码、派生凭据、JWT/JTI、授权票据、剪贴板或文件正文。文件事件只接受 basename，不能借文件名记录任意目录路径；事件种类、长度、大小、字段及频率均受服务端约束。每个授权最多 1024 条浏览器报告，每秒最多 4 条；该 HTTP 路由独立限制 600 条/分钟，避免与默认 API 限流混用。

浏览器报告不等同于独立服务端证据，不能证明目标应用已经粘贴、远端文件已经落盘或原生认证已经由 Console 验证。断网、限流及审计存储失败可能使报告缺失；不能据此声称内容级审计完整或无丢失。原生公共审计上报的现有来源验证局限保持原有边界。

准许审计失败时不发可用票据。拒绝和结束记录写入失败只输出无秘密的诊断，不放行连接，也不延长已经结束的会话。
